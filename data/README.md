# Данные и разбиения

В `metadata/` лежат сохранённые каталоги источников, манифесты отрезков, очередь ручной проверки и пользовательские отзывы. В `splits/` — фактически использованные разделения UCF101, адаптаций и финального набора. Полные медиафайлы и веса хранятся отдельно и исключены из Git.

- `splits/train.csv`, `val.csv`, `test.csv` — UCF101: 297/60/61 клип, разделённые по исходным группам.
- `splits/adapt_*.csv` — короткая адаптация на MultiSports.
- `splits/mixed_*.csv` — смешанная адаптация UCF101/MultiSports.
- `splits/vk_owner_holdout/*.jsonl` — финальное разделение по публикующим аккаунтам: 766/155/165 окон, 277/58/61 группа.
- `metadata/vk_visual_corrections.json` — десять исправлений вида спорта, применяемых поверх исходного архива.

Для повторения UCF101 существующие скрипты скачивают и извлекают первый shard в `data/raw/` и `data/processed/`. Эти каталоги не включены в подготовленную папку. Для повторения ранних внешних проверок нужны соответствующие медиа из исходной рабочей папки или уже реализованных выборочных загрузчиков; доступ к MultiSports/SportsShot должен быть одобрен на Hugging Face. Токен передаётся через локальную авторизацию или переменную окружения, в репозиторий он не записывается.

Для основного обучения полный переданный архив должен лежать в корневом `sports_training_bundle/`, включая `frames/`. В Git сохранены его метаданные и исходные JSONL; это сохраняет точные идентификаторы и контрольные суммы split, но не заменяет кадры. Небольшой `demo/sample_bundle/` покрывает только существующее демо.

Пути в CSV/JSONL относительны к корню проекта или архива, как в исходной реализации. Заголовки и описания сохранены для объяснения происхождения слабых меток и не подаются в визуальную модель.
